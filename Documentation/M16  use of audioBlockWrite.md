# M16 use of `audioBlockWrite()`

`audioBlockWrite(left, right)` is the standard output function for new M16 sketches on ESP8266, ESP32, Pico/Pico 2, and Teensy 4.x. Call it exactly once for every frame generated by `audioUpdate()`.

```cpp
void audioUpdate() {
  int32_t sample = oscillator.next();
  audioBlockWrite(sample, sample);
}
```

M16 accepts 32-bit working values and clips each channel to the 16-bit output range at the final output stage. Intermediate mixing should still be scaled sensibly so that intentional detail is not lost to final clipping.

## Why use `audioBlockWrite()`

The same sketch-level call adapts to the active platform and audio mode:

- In the normal dedicated-core mode, it submits audio through the platform's buffered output path.
- In ESP32 dual-core partition mode, it collects each core's partial voice mix, combines matching blocks, applies optional master processing, and performs one ordered DMA write.
- In Pico-family partition mode, it collects the two voice partitions and Core 1 combines, post-processes, and writes them.
- On Teensy 4.x, it fills the blocks supplied by the Teensy AudioStream system.
- On ESP8266 and internal-DAC modes, it forwards through the appropriate platform output path.

The old `i2s_write_samples()` name remains only as a deprecated compatibility wrapper for legacy sketches. It is rejected in block-partitioned mode. Use `audioBlockWrite()` in all new code.

## Default: one dedicated audio core

M16 defaults to a single audio renderer on ESP32 and Pico-family boards. This is the appropriate mode for most sketches, particularly serial or interrelated signal paths such as:

- One oscillator or one monophonic voice
- FM or phase-modulation cascades
- Shared feedback networks
- Master delays, reverbs, filters, or physical models
- Any graph whose stages depend on one another's current state

```cpp
void setup() {
  // This is currently the default, but stating it documents the design.
  setIsDualCore(false);
  audioStart();
}

void audioUpdate() {
  int32_t modulator = modOsc.next();
  int32_t sample = carrier.phMod(modulator, 2.0f);
  audioBlockWrite(sample, sample);
}
```

In this mode, do not use `i2s_write_samples()` for lower latency: it now forwards to the same block writer. `audioBlockWrite()` is the supported portable path.

## Optional dual-core voice partitioning

Call `setIsDualCore(true)` before `audioStart()` only when `audioUpdate()` can divide an array of independent, stateful voices between two cores. Typical per-voice state includes:

- `Osc`, `Env`, `SVF`, or `SVF2` objects
- Per-voice delays, physical models, or sample players
- Other polyphonic voice objects which do not share audio-rate history

Use `audioPartitionOffset()` and `audioPartitionStride()` rather than hard-coding core numbers:

```cpp
void audioUpdate() {
  int32_t left = 0;
  int32_t right = 0;

  for (int voice = audioPartitionOffset();
       voice < VOICE_COUNT;
       voice += audioPartitionStride()) {
    int32_t sample = voices[voice].next();
    left += sample >> 3;
    right += sample >> 3;
  }

  // Each active partition must submit exactly one partial frame.
  audioBlockWrite(left, right);
}
```

When partitioning is active, the helpers normally select interleaved voices: one partition processes voices 0, 2, 4… and the other processes 1, 3, 5…. If dual-core startup is unavailable, they safely return offset 0 and stride 1 so the remaining renderer processes every voice.

`audioBlockWrite()` accumulates `M16_BLOCK_SIZE` frames per partition (32 by default). The finalizer combines corresponding partial blocks before output. Do not manually add the other partition.

On a Pico or Pico 2, use the portable loop pattern below when partitioning is enabled. `audioLoop()` services bounded Core-0 jobs on Pico; it is effectively a no-op when Pico 2's automatic doorbell worker is available.

```cpp
void loop() {
  audioLoop();
  // UI, MIDI, sequencing, and other application work
}
```

## Post-combine master effects

A shared, stateful effect must receive the complete mix and must advance exactly once per output frame. Register it with `setAudioPostProcessCallback()`:

```cpp
FX effects;

void processMasterEffects(int32_t& left, int32_t& right) {
  int32_t wetLeft;
  int32_t wetRight;
  effects.reverbStereoInterp(left, right, wetLeft, wetRight);
  left = wetLeft;
  right = wetRight;
}

void setup() {
  effects.initReverbSafe();
  setAudioPostProcessCallback(processMasterEffects);
  setIsDualCore(true);
  audioStart();
}
```

In partitioned mode, M16 calls this callback after combining the two partial mixes and before final clipping/output. In dedicated-core mode it still runs once immediately before output, so the same structure is portable between modes.

Suitable post-processing includes:

- Reverb, chorus, and master delay
- Compression or limiting
- Master filters
- Distortion or bit crushing
- Master gain, panning, and final mix processing
- Any nonlinear effect that should operate on the summed signal
- Any effect with shared history or feedback

Per-voice effects with one independent instance per voice remain inside the partitioned voice loop.

Do not apply a master effect only under `audioIsFinalizerCore()` inside `audioUpdate()`. At that point the local mix still contains only that partition's voices. `audioIsFinalizerCore()` identifies the finalizer; it does not combine partial mixes.

## Delay example for the post-process callback

```cpp
void processMasterEffects(int32_t& left, int32_t& right) {
  int32_t dryLeft = left;
  int32_t dryRight = right;

  int32_t delayedLeft = delayLeft.next(clip16(dryLeft));
  int32_t delayedRight = delayRight.next(clip16(dryRight));

  left = clip16(dryLeft + delayedLeft);
  right = clip16(dryRight + delayedRight);
}
```

Each stereo channel needs its own stateful delay instance. The explicit clipping before `next()` is appropriate when that class accepts a 16-bit input and the combined dry mix might exceed that range.

## Complete polyphonic reverb example

```cpp
#include "M16.h"
#include "Osc.h"
#include "FX.h"

constexpr int VOICE_COUNT = 8;

WaveTable wavetable;
Osc voices[VOICE_COUNT];
FX effects;

void processMasterEffects(int32_t& left, int32_t& right) {
  int32_t wetLeft;
  int32_t wetRight;
  effects.reverbStereoInterp(left, right, wetLeft, wetRight);
  left = wetLeft;
  right = wetRight;
}

void setup() {
  wavetable.sawGen();
  for (int i = 0; i < VOICE_COUNT; ++i) {
    voices[i].setTable(wavetable);
    voices[i].setPitch(48 + i);
  }

  effects.initReverbSafe();
  effects.setReverbLength(0.5f);
  effects.setReverbMix(0.25f);

  setAudioPostProcessCallback(processMasterEffects);
  setIsDualCore(true);
  audioStart();
}

void loop() {
  // Required to contribute Core-0 partition work on Pico.
  // Harmless/no-op where cooperative service is unnecessary.
  audioLoop();
}

void audioUpdate() {
  int32_t left = 0;
  int32_t right = 0;

  for (int voice = audioPartitionOffset();
       voice < VOICE_COUNT;
       voice += audioPartitionStride()) {
    int32_t sample = voices[voice].next();
    left += sample >> 3;
    right += sample >> 3;
  }

  audioBlockWrite(left, right);
}
```

## Incorrect patterns

Do not process every stateful voice on both renderers:

```cpp
// Wrong in partitioned mode: every voice advances twice.
for (int i = 0; i < VOICE_COUNT; ++i) {
  mix += voices[i].next();
}
audioBlockWrite(mix, mix);
```

Do not process a shared reverb separately on each partial mix:

```cpp
// Wrong: the reverb receives two incomplete mixes and its state is shared.
effects.reverbStereo(mix, mix, left, right);
audioBlockWrite(left, right);
```

Do not conditionally omit the writer:

```cpp
// Wrong: every audioUpdate invocation must submit exactly one frame.
if (voiceIsActive) {
  audioBlockWrite(sample, sample);
}
```

Submit silence when necessary instead:

```cpp
audioBlockWrite(voiceIsActive ? sample : 0,
                voiceIsActive ? sample : 0);
```

Avoid allocation, `Serial.print()`, blocking I/O, and general-purpose `rand()` inside `audioUpdate()` or the post-process callback. Initialize buffers before `audioStart()` and use `audioRand()` when audio-rate randomness is required.

## Practical decision rule

```text
Does audioUpdate contain an array of independent voices?
├── No
│   └── Keep the default dedicated-core mode and use audioBlockWrite().
└── Yes
    ├── Does the complete graph fit comfortably on one audio core?
    │   └── Yes: dedicated-core mode remains the simplest option.
    └── Is more DSP capacity required?
        ├── Enable setIsDualCore(true) before audioStart().
        ├── Partition voices with audioPartitionOffset()/Stride().
        ├── Submit each partial frame with audioBlockWrite().
        └── Put shared/master effects in setAudioPostProcessCallback().
```

For all new M16 sketches, `audioBlockWrite()` is the correct output API regardless of which branch is selected.
